# AI Red Teaming

LLM 기반 시스템을 실제 공격자 관점에서 시험해 취약점을 찾는 활동. 전통적인 침투 테스트와 달리 모델의 **확률적 출력**을 다루기 때문에, 한 번 통과했다고 안전하다고 말할 수 없다는 점이 핵심 차이다.

## 내가 이해한 구조

레드팀 활동은 크게 세 층으로 나뉜다.

1. 입력 조작 — [[프롬프트 인젝션]]이 대표적이다.
2. 방어 우회 — [[가드레일 우회 탐지]]가 여기 해당한다.
3. 파이프라인 공격 — 모델 자체보다 주변 구성요소를 노린다. [[RAG 보안]] 참고.

## 성숙도에 대한 내 판단

방법론은 빠르게 정리되고 있지만 **표준화된 벤치마크가 아직 없다.** 회사마다 자체 체크리스트를 쓰는 단계라, 나는 이 분야를 아직 "프로토타입" 수준으로 본다. 상용 도구가 나오고는 있으나 평가 기준이 제각각이다.

## 남은 질문

- 자동화 레드팀 도구의 결과를 어떻게 재현 가능하게 만들 것인가?
- 모델 업데이트마다 전체 레드팀을 다시 돌려야 하는가?
