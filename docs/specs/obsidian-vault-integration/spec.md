# Obsidian Vault Integration (LLM Wiki)

## User-visible outcome

사용자가 자기 Obsidian vault 경로를 지정하면, 대시보드가 그 노트들을 읽어 실제 지식 그래프를 그리고, 노트에 정리해 둔 내용을 근거로 기술 동향을 보여주며, LUMI에게 자기 노트를 근거로 질문할 수 있게 된다.

## Approved scope

- 대시보드에서 vault 폴더 경로를 입력·변경할 수 있고, 그 경로는 다음 방문에도 유지된다.
- vault의 마크다운 노트를 읽어 노트 제목과 `[[위키링크]]` 관계를 파악한다. 앱은 vault를 **읽기만** 한다.
- **연구 동향**: 카테고리-키워드 관계도 대신, vault 노트를 노드로 하고 노트 사이 `[[위키링크]]`를 간선으로 하는 실제 지식 그래프를 보여준다.
- **기술 동향**: 뉴스 대신 vault 노트 내용을 근거로 각 주제의 성숙도 단계와 근거를 보여준다.
- **LUMI 채팅**: 근거 소스를 "위키" / "뉴스" 중에서 사용자가 고른다. 기본값은 위키다. 선택한 소스가 답변 근거로 전달된다.
- **뉴스 패널**: 지금 동작 그대로 유지한다. 다만 더 이상 연구 동향·기술 동향의 근거가 아니다.
- vault 경로가 없거나 잘못됐거나 노트가 없으면, 각 패널이 그 사실을 안내한다.
- 저장소에 예시 vault(`sample-vault/`)를 포함해, 실제 vault가 없어도 동작을 확인할 수 있게 한다.

## Acceptance criteria

- [ ] vault 경로를 입력하면 연구 동향 카드에 그 vault의 실제 노트 제목들이 노드로 표시되고, `[[위키링크]]`로 연결된 노트끼리 선으로 이어진다.
- [ ] vault의 노트를 고치거나 추가한 뒤 새로고침하면 그래프에 반영된다.
- [ ] 기술 동향을 실행하면, 각 주제의 단계와 근거가 **vault 노트에 실제로 적힌 내용**을 반영해 표시된다(뉴스 기사 내용이 아니다).
- [ ] LUMI 채팅에서 "위키"를 고르고 질문하면, vault 노트 내용을 근거로 한 답이 온다.
- [ ] LUMI 채팅에서 "뉴스"를 고르고 질문하면, 기존처럼 수집된 뉴스를 근거로 한 답이 온다.
- [ ] vault 경로를 지정하지 않은 상태에서도 앱이 깨지지 않고, 각 패널이 vault를 지정하라는 안내를 보여준다.
- [ ] 존재하지 않는 경로를 넣으면 이해할 수 있는 오류 안내가 표시된다.
- [ ] vault 경로는 새로고침 후에도 유지된다.
- [ ] 앱을 사용해도 vault 안의 파일이 변경되지 않는다.

## Settled constraints and rationale

- 중심 지식 소스는 vault이고 뉴스는 별도 패널로 남으며, LUMI 채팅만 두 소스를 선택 가능하다 — [docs/decisions/knowledge-source-precedence.md](../../decisions/knowledge-source-precedence.md) 참고.
- 기술 동향과 LUMI 답변 생성은 로컬 `claude` CLI를 쓴다 — [docs/decisions/local-claude-cli-runtime.md](../../decisions/local-claude-cli-runtime.md) 참고. 따라서 이 기능들도 로컬 실행 시에만 동작한다.
- 개인용 단일 사용자 도구이며 vault는 사용자 본인 것 하나만 다룬다(PRODUCT.md 경계 계승).

## Assumptions

- vault 경로는 브라우저 `localStorage`에 저장한다(카테고리·키워드와 같은 방식).
- 노트 제목은 파일명(확장자 제외)으로 삼는다. Obsidian의 기본 동작과 같다.
- `[[링크]]`의 별칭(`[[노트|표시이름]]`)과 헤딩 참조(`[[노트#섹션]]`)에서는 노트 이름 부분만 취한다.
- vault 하위 폴더의 노트도 모두 포함하되, `.obsidian` 같은 점으로 시작하는 폴더는 건너뛴다.
- 그래프에 표시하는 노트 수에는 상한을 둔다. 노트가 아주 많은 vault에서 화면이 뭉개지는 것을 막기 위함이다.
- 기술 동향이 다루는 주제는 vault 노트 제목이며, 카테고리 키워드가 아니다.

## Off-limits (and why)

- vault에 노트를 쓰거나 고치는 기능 — 이번 범위는 읽기 전용이다. 쓰기가 들어오면 데이터 손실 위험이 생기므로 별도로 다룬다.
- Obsidian 앱 자체와의 실시간 연동(플러그인, URI 스킴 등) — 파일을 직접 읽는 것만으로 목적이 달성되고, 플러그인은 별도 배포 문제를 만든다.
- 벡터 검색·임베딩 기반 검색 — 노트 수가 적은 개인 vault에서는 전체를 컨텍스트로 넘기는 것으로 충분하다. 노트가 많아져 한계가 확인되면 그때 다룬다.
- 뉴스 패널의 동작 변경 — 이미 검증된 기능이므로 이번에 건드리지 않는다.

## Deferred

- vault 노트가 아주 많을 때의 검색·요약 전략(임베딩 등)은 실제로 한계가 확인되면 다룬다.
- 뉴스에서 본 내용을 vault 노트로 저장하는 흐름은 이후 논의한다.
- 그래프에서 노트를 클릭해 내용을 보거나 Obsidian에서 열기는 이후 논의한다.

## Remaining risks

- 이 저장소의 `PRODUCT.md`는 아직 뉴스 중심으로 서술되어 있어 이 스펙과 어긋난다. 제품 정의 자체를 갱신하는 것은 이 스펙의 범위가 아니므로, 별도로 제품 정의를 다시 정리해야 한다.
- 사용자 실제 vault가 아직 없어, 이번 검증은 저장소에 포함한 예시 vault로만 이루어진다. 실제 vault의 규모·구조에서 생기는 문제는 확인되지 않은 상태로 남는다.
- 노트 전체를 컨텍스트로 넘기므로, 노트가 길거나 많아지면 기술 동향·LUMI 응답이 느려지거나 일부 내용이 누락될 수 있다.
- 앱이 임의의 로컬 폴더를 읽으므로, 사용자가 vault가 아닌 민감한 폴더를 지정하면 그 안의 마크다운 내용이 화면과 LLM 컨텍스트에 노출된다.
