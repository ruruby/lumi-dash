# External Source Pool vs Vault

## Decisions

- Collector가 수집한 외부 자료는 Vault에 바로 들어가지 않는다. `후보 자료`로 **Vault 밖의 앱 로컬 저장소**에 쌓이고, Research Inbox에 후보로 제시된다.
- 후보 자료가 Vault로 넘어가는 **유일한 경로는 사용자의 `Add to Wiki`**다. 수집·분석·점수화는 사용자를 대신해 저장 결정을 내리지 않는다.
- `Add to Wiki`는 원문을 그대로 옮기지 않는다. LLM이 구조화된 노트 초안을 만들어 **먼저 화면에 보여주고, 사용자가 확정한 뒤에만** 파일로 저장한다.
- 저장은 **신규 파일 생성만** 한다. 이 앱은 기존 노트를 수정하거나 삭제하지 않는다.
- 내장 샘플을 쓸 때는 초안까지만 보여주고 실제 파일을 쓰지 않는다.

## Boundaries

- 이 결정은 외부에서 수집한 자료가 Vault 지식이 되는 경로 전체에 적용된다. 새 Collector(논문·White Paper·Advisory·뉴스 등)를 추가할 때도 같은 경계를 따른다.
- 화면에 표시되는 지식이 Vault에서 왔는지 뉴스에서 왔는지는 [knowledge-source-precedence](knowledge-source-precedence.md)가 정한다. 이 문서는 그 경계를 넘는 **쓰기 방향**만 다룬다.
- 어떤 런타임으로 초안을 생성하는지는 [local-claude-cli-runtime](local-claude-cli-runtime.md)이 정한다.

## Why

이 앱은 원래 Vault를 읽기만 했다. `knowledge-source-precedence`의 재검토 조건에 "외부 자료를 vault 노트로 저장하는 흐름을 만들 때"가 명시돼 있었고, Research Collector가 정확히 그 조건을 발동시켜 이 결정으로 갱신했다.

쓰기를 허용하되 후보 풀을 사이에 둔 이유는, 자동 저장이 Vault를 raw data dump로 만들기 때문이다. Vault의 가치는 "사용자가 직접 읽고 판단해서 정리한 결론"이라는 데서 나오는데, 수집기가 발견한 자료를 그대로 넣으면 소화되지 않은 외부 정보와 사용자의 결론이 같은 공간에서 구분되지 않는다. 후보 풀을 Vault 밖에 두면 수집량을 늘려도 Vault는 오염되지 않는다.

초안을 먼저 보여주는 이유는 두 가지다. LLM이 만든 노트가 사용자 확인 없이 Vault에 남으면 잘못된 요약이 이후 모든 분석의 근거가 된다. 그리고 이 앱의 다른 AI 기능과 달리 이것만 되돌리기 어려운 결과(사용자 파일)를 남긴다.

기존 노트를 건드리지 않는 이유는, 사용자가 Obsidian에서 직접 편집하는 파일과 앱이 만든 파일이 충돌하면 사용자가 잃는 쪽이 자기 글이기 때문이다.

## Reconsider when

- 사용자가 Inbox를 거치지 않고 특정 신뢰 Source는 자동 저장하기를 원할 때. 그때도 자동 저장 대상 Source의 범위를 명시적으로 좁혀야 한다.
- 앱이 기존 노트에 링크나 태그를 덧붙여야 할 실제 필요가 생겼을 때. 그때는 편집 충돌 처리 방식을 먼저 정한다.

## Still-rejected alternatives

- 수집한 자료를 전부 Vault에 저장하고 나중에 정리 — Vault가 raw dump가 되어 "정리된 결론"이라는 성격을 잃음; 후보 풀 없이 쓰겠다는 요구가 생기면 재검토.
- 확인 없이 즉시 파일 생성 — 클릭 수는 줄지만 검증되지 않은 AI 생성물이 사용자 파일로 남고, PRODUCT.md의 "AI의 추천과 생성 결과는 항상 사용자 통제 아래 둔다" 원칙에 어긋남.
- 쓰기 없이 초안 복사/다운로드만 제공 — 읽기 전용 경계는 지키지만 Discover→Remember 흐름이 앱 밖에서 끊기고, 사용자가 매번 수동으로 옮겨야 함.
- 후보 풀을 Vault 안(예: vault 하위 `.lumi/`)에 저장 — 외부 정보와 사용자 지식의 분리가 무너지고, Obsidian의 검색·그래프에 후보 자료가 섞임.
